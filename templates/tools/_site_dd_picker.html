{# The item picker: one control per room or unit, not one per item. WHY
AND NOT A SCRIPTED SHEET It opens, closes and submits with JavaScript disabled, because the browser implements it. The bottom-sheet presentation is pure CSS on [open], so a phone gets a sheet and a desktop gets an inline panel from the same markup and neither depends on a script running. The only JavaScript here is the search box, which is hidden until a script reveals it -- an inspector with JS off sees the full list instead of a filter that does nothing, which is the right failure. WHY IT DECLARES NO
OF ITS OWN It renders inside the room's (or unit's) answer form, and HTML has no nested forms -- a browser would silently drop the inner one and the first tap would post the room's answers to the add-item route. So the controls belong to a form declared alongside, by id, exactly as the capture and instance buttons already do on these pages. Every entry is a submit button carrying its own key. No radio to select then confirm: one tap adds the item, because the inspector is standing in front of the thing and holding the phone in one hand. #} {% macro item_picker(scope, groups, form_id) %}
